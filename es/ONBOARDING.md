# Checklist de Onboarding

Para nuevos miembros del equipo. Seguilo en orden.

---

## Día 1 — Acceso

- [ ] Acceso al repositorio GitHub
- [ ] Acceso a la documentación del proyecto (`docs/`)
- [ ] Acceso a las herramientas de comunicación (Discord, etc.)

---

## Día 2 — Contexto

- [ ] Leé `docs/PRD.md` — qué es el proyecto
- [ ] Leé `docs/architecture/adr/` — decisiones de arquitectura (empezá por las más recientes)
- [ ] Leé `docs/architecture/rfc/` — discusiones abiertas o decisiones recientes
- [ ] Leé `docs/FAQ.md` — preguntas frecuentes

---

## Día 3 — Templates

- [ ] Revisá `docs/templates/` — los templates que vas a usar
- [ ] Entendé `ADR_template.md` — cómo se registran las decisiones
- [ ] Entendé `RFC_template.md` — cómo se discuten las propuestas

---

## Día 4 — Primera Contribución

- [ ] Elegí una tarea pequeña (bug fix o feature menor)
- [ ] Actualizá los docs relevantes si la tarea los toca
- [ ] Abrí un PR con las actualizaciones de documentación

---

## Tips

- Si algo no está documentado, **preguntá sin miedo** — luego documentalo.
- Los ADRs existen para que NO tengas que preguntar "por qué se hizo así?" — están todos ahí.
- La carpeta `docs/` es la fuente de verdad única.

---

## Archivos Clave

| Archivo | Propósito |
|---------|-----------|
| `docs/PRD.md` | Qué es este proyecto |
| `docs/architecture/adr/` | Decisiones pasadas |
| `docs/architecture/rfc/` | Propuestas abiertas |
| `docs/templates/` | Templates para todos los docs |
