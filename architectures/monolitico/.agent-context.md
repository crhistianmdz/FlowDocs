## Working with User Stories (HUs)

### Backlog Location
Las Historias de Usuario viven en: `docs/tasks/*.md`

### Command to Work on a HU
```bash
/sdd-new <hu-name> --from-docs
```

**Example:**
```bash
/sdd-new HU-001-user-login --from-docs
/sdd-new HU-002-product-crud --from-docs
```

**What happens:**
1. Orchestrator reads `docs/tasks/<hu-name>.md`
2. Passes HU content as context to sub-agents
   > See [ADR-009: SDD Sub-agent Context Pattern](../docs/architecture/adr/009-sdd-subagent-context-pattern.md) for the formal specification of how context is injected to sub-agents.
3. Creates artifacts in `openspec/changes/<hu-name>/`
4. Follows SDD flow: proposal → spec → design → tasks → apply → verify → archive

**⚠️ Importante**: siempre usar `--from-docs`. Sin ese flag, el agente NO lee la HU y genera todo desde cero.

### HU Template
See: `docs/tasks/TEMPLATE.md`

### HU Naming Convention
```
HU-001-<short-description>.md
HU-002-<short-description>.md
```

**Examples:**
- `HU-001-user-login.md`
- `HU-002-product-crud.md`
- `HU-003-bulk-upload.md`

## Team Workflow

### For All Team Members

```bash
# 1. Start session (bootstrap personal Engram)
/sdd-init

# 2. Sync with team (get latest changes)
git pull origin main

# 3. Work on a HU
/sdd-new HU-XXX-name --from-docs

# 4. Commit and push (share with team)
git add .
git commit -m "feat: HU-XXX - description"
git push origin main
```

### Artifact Store Mode
- **Mode**: `hybrid` (files in `openspec/` + personal Engram cache)
- **Shared**: `openspec/changes/<change-name>/` (visible to all via Git)
- **Personal**: Engram (cross-session recovery, semantic search)
