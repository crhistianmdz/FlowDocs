## Working with User Stories (HUs)

### Module-Specific HUs

```bash
# Working on auth-service
/sdd-new HU-001-auth-login --from-docs --module=auth-service

# Working on inventory-service
/sdd-new HU-002-stock-update --from-docs --module=inventory-service

# Working on orders-service
/sdd-new HU-003-create-order --from-docs --module=orders-service
```

**What happens:**
1. Orchestrator reads `docs/<module>/tasks/<hu-name>.md`
2. Passes HU content as context to sub-agents
3. Creates artifacts in `openspec/changes/<hu-name>/`
4. Follows SDD flow: proposal → spec → design → tasks → apply → verify → archive

**⚠️ Importante**: siempre usar `--from-docs`. Sin ese flag, el agente NO lee la HU y genera todo desde cero.

### Cross-Module HUs

```bash
# Working on something that affects multiple modules
/sdd-new HU-010-order-flow --from-docs --module=SHARED
```

**Use case**: Features that span multiple services (e.g., "complete order flow" touches auth, inventory, orders).

### HU Template
See: `docs/<module>/tasks/TEMPLATE.md` or `docs/SHARED/tasks/TEMPLATE.md`

### HU Naming Convention
```
HU-001-<module>-<short-description>.md
```

**Examples:**
- `HU-001-auth-login.md` (auth-service)
- `HU-002-inventory-crud.md` (inventory-service)
- `HU-003-orders-create.md` (orders-service)

## Team Workflow

### For All Team Members

```bash
# 1. Start session (bootstrap personal Engram)
/sdd-init

# 2. Sync with team (get latest changes)
git pull origin main

# 3. Identify which module you're working on
# Check docs/SHARED/arquitectura.md or ask team

# 4. Work on a HU
/sdd-new HU-XXX-name --from-docs --module=<module-name>

# 5. Commit and push (share with team)
git add .
git commit -m "feat(<module>): HU-XXX - description"
git push origin main
```
